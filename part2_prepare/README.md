# Часть 2. CLI-утилита подготовки данных

Две команды на `argparse`: `prepare` собирает файлы каталога в один
массив `.npy`, `doctor` проверяет окружение.

## Запуск

```bash
cd part2_prepare

# изображения (рекурсивно, с масштабированием)
python -m app.cli prepare --path ../data/input/images --ext .png

# CSV-таблицы
python -m app.cli prepare --path ../data/input/tables --ext .csv \
    --output ../data/output/tables.npy

# с ограничением и другим размером
python -m app.cli prepare --ext .png --limit 30 --size 32

# проверка окружения
python -m app.cli doctor
python -m app.cli doctor --json
```

## Ключи команды prepare

| Ключ | Значение |
|---|---|
| `--path` | каталог с исходными файлами |
| `--ext` | расширения: `--ext .png .jpg` |
| `--output` | итоговый файл `.npy` |
| `--size` | сторона изображения после масштабирования |
| `--limit` | обработать не больше N файлов |
| `--no-normalize` | не нормировать значения |
| `--log-level`, `--log-file` | настройки логов |
| `--env-file` | путь к `.env` |

## Настройки из окружения

Читаются переменные с префиксом `NN_` (см. `.env.example` в корне):
`NN_DATA_DIR`, `NN_OUTPUT_DIR`, `NN_EXTENSIONS`, `NN_IMAGE_SIZE`,
`NN_LOG_LEVEL`, `NN_LOG_FILE`, `NN_MAX_FILES`.

Приоритет: аргументы CLI > переменные окружения > значения по
умолчанию. Абсолютных путей в коде нет: значения из окружения
разрешаются от корня проекта, пути из CLI - от текущего каталога.

## Что происходит внутри

1. `DirectoryScanner.scan()` обходит каталог через `Path.rglob("*")`,
   отбрасывает скрытые папки и файлы с другими расширениями.
2. Изображения читаются через Pillow, переводятся в оттенки серого,
   масштабируются к `--size` и делятся на 255.
3. CSV читаются модулем `csv` с автоопределением разделителя
   (`;` или `,`), затем масштабируются методом min-max по столбцам.
4. Массивы складываются в стек, статистика (число файлов, форма,
   диапазон, время) печатается и сохраняется рядом с `.npy`
   в файле `*.meta.json`.

## Исключения

`PrepareError` -> `ConfigError`, `ScanError`, `EmptySelectionError`,
`UnsupportedFormatError`. Ошибка чтения одного файла не прерывает
обработку: файл попадает в список пропущенных с записью в лог.
